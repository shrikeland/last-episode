# Блок «Продолжить» наверху библиотеки

## Проблема
Человек заходит вечером с одним намерением: досмотреть то, что начал. Библиотека вместо этого показывает всю коллекцию, разложенную по типам и отсортированную по году выхода. Тайтлы в статусе «Смотрю» разбросаны по четырём секциям, и на какой серии он остановился в каждом — надо вспоминать, заходя внутрь.

Это главный сценарий продукта, и сейчас он самый неудобный.

## Что видит пользователь
Первый блок на странице библиотеки, до фильтров и секций по типам: горизонтальный ряд карточек тайтлов в статусе «Смотрю», у которых есть непросмотренные серии.

Каждая карточка — постер, название, и главное: **следующая серия** конкретно (`S2 · Серия 8 · Название`), прогресс-бар и кнопка отметить её просмотренной прямо здесь. После отметки карточка на месте обновляется на следующую серию; когда серии кончаются — уезжает из блока.

Сортировка внутри блока — по дате последнего просмотра, свежее слева. Тайтлов без начатого просмотра в блоке нет — они и так в библиотеке.

Если тайтлов «Смотрю» нет вообще, блок не рендерится совсем. Пустой блок с текстом «нечего продолжать» хуже, чем его отсутствие.

## Почему это дёшево / дорого
Половина данных считается: `getEpisodeProgressMap` (`lib/supabase/media.ts`) уже отдаёт `watched/total` по тайтлу, и библиотека его вызывает — `app/(app)/library/page.tsx:61`.

Чего нет: функции «дай следующую непросмотренную серию для каждого тайтла». Сейчас все выборки серий в `lib/supabase/progress.ts` работают от одного `media_item_id` (`getSeasonsWithEpisodes`), то есть N запросов на N тайтлов. Нужна одна выборка на все тайтлы «Смотрю» сразу, иначе блок утянет страницу вниз по времени.

Отметка серии из блока переиспользует `toggleEpisode` из `app/actions/progress.ts` — там ничего дописывать не надо. Но блок придётся сделать клиентским с оптимистичным обновлением, как `SeasonAccordion`.

> **Уточнено 2026-09-22 при планировании.** Голого `toggleEpisode` не хватит: после отметки блоку нужна следующая серия, которую клиент не знает, поэтому нужен новый action `watchNextEpisode`, который её возвращает. «Один запрос на все» тоже не выходит — упирается в лимит PostgREST в 1000 строк и в порядок по `season_number`. План: по запросу с `limit(1)` на тайтл, параллельно. Подробности в `plans/continue-watching.md`.

## Скоуп
- `lib/supabase/progress.ts` — `getNextUnwatchedEpisodes(client, mediaItemIds)`, один запрос на все
- `components/library/ContinueWatching.tsx` — новый клиентский компонент с оптимистичной отметкой
- `app/(app)/library/page.tsx` — выбрать тайтлы «Смотрю», подгрузить следующие серии, отрендерить блок
- `app/actions/progress.ts` — `watchNextEpisode`, отмечает серию и возвращает следующую (добавлено при планировании)
- Миграция БД: не нужна
- `'use client'`: нужен — отметка серии без перезагрузки
- Внешние вызовы: нет

## Чего НЕ делаем
Без отметки нескольких серий подряд из блока — одна кнопка, одна серия. Без фильмов в блоке: у них нет серий, и «продолжить» для них ничего не значит. Без блока на других страницах — только библиотека. Без ручного порядка карточек.

## Открытые вопросы
- Что делать с тайтлом в «Смотрю», у которого все известные серии отмечены, но сериал не закончен — сезон вышел не целиком? Прятать из блока или показывать с пометкой «ждём новые серии»?
- Сортировка по дате последнего просмотра требует `MAX(watched_at)` по тайтлу — это ещё одна агрегация. Может, хватит порядка по `media_items.updated_at`?

**Решено при планировании (2026-09-22):** тайтл без непросмотренных созданных серий из блока прячем. `updated_at` не подходит — триггер не срабатывает при отметке серии, сортируем по `watched_at`.
