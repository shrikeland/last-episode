# «Что у нас общего» на профиле друга

## Проблема
Я открываю профиль друга и вижу его библиотеку целиком — сотню постеров, разложенных по типам. Чтобы понять, насколько совпадают наши вкусы и что из его любимого я ещё не видел, приходится сравнивать в голове с собственной библиотекой. Никто так не делает — поэтому профиль друга открывают один раз и больше не возвращаются.

## Что видит пользователь
Над библиотекой друга — блок из двух рядов:

1. **«Смотрели оба»** — число совпадений («У вас 23 общих тайтла») и горизонтальный ряд постеров, где у каждого две оценки: его и моя. Сначала — где оценки расходятся сильнее всего: это самое интересное
2. **«Его любимое, которого нет у тебя»** — тайтлы, которые друг оценил на 8+ и которых нет в моей библиотеке. На постере кнопка «Добавить» — та же, что уже есть в профиле

Если совпадений нет — первый ряд заменяется строкой «Пока ни одного общего тайтла». На своём профиле блок не показывается.

## Почему это дёшево / дорого
- Библиотека друга уже загружена целиком — `getUserProfile()` в `app/actions/users.ts:71` возвращает `mediaItems`. Моя загружается через `getMediaItems(supabase, user.id)` из `lib/supabase/media.ts`. Пересечение по `tmdb_id` — чистая функция на массивах, без новых запросов к БД
- Карточку с кнопкой добавления можно собрать из `components/profile/ProfileMediaCard.tsx` и `ProfileAddToLibraryControl.tsx`, горизонтальный ряд — из `components/library/ScrollRow.tsx`
- Новое — сама вёрстка карточки с двумя оценками и логика сортировки по расхождению. Отсюда M, а не S
- Для пересечения нужно знать, кто смотрит: `getServerUser()` на странице профиля уже вызывается внутри `getUserProfile`
- Сверка с кодом 2026-09-24 (см. «Сверка с кодом» ниже): страница профиля пока не знает ни «свой ли это профиль», ни «друг ли это» — нужна выборка id друзей

## Скоуп
- `lib/compare.ts` — чистая функция `compareLibraries(mine, theirs)` → `{ common, theirFavoritesMissing }`, легко покрыть тестом
- `components/profile/CommonTitles.tsx` — новый компонент
- `app/(app)/profile/[username]/page.tsx` — загрузить мою библиотеку, вставить блок
- Миграция БД: не нужна
- `'use client'`: только для кнопки «Добавить», она уже клиентская
- Внешние вызовы: нет

## Чего НЕ делаем
Никакого «процента совместимости вкусов» одной цифрой — это выдумка, которая выглядит как наука. Никакого AI-объяснения, почему вкусы совпадают. Не сравниваем прогресс по сериям. Не показываем блок на профилях не-друзей в первой версии.

## Сверка с кодом (2026-09-24, pick)
- **`tmdb_id` не уникален между фильмами и сериалами.** У TMDB это разные пространства id. Совпадение считаем по `tmdb_id` + род TMDB (`movie`/`animation` → фильм, `tv`/`anime` → сериал), а не по точному `type`: `anime`/`animation` вычисляются по жанрам при добавлении и могут разойтись у двух людей
- **«Свой профиль» и «друг» нигде не определяются.** `getUserProfile` проверяет только авторизацию и `is_library_public`; дружба на странице профиля не учитывается. Нужна выборка принятых дружб — параллельно с профилем, в новом `app/actions/compare.ts`, `getUserProfile` не трогаем
- **`ProfileMediaCard` оценку не показывает**, а статус и тип занимают всю высоту карточки — для двух оценок нужна своя компактная карточка; `ProfileAddToLibraryControl` переиспользуется как есть
- **В библиотеке есть «Хочу посмотреть».** «Смотрели оба» без фильтра показывал бы тайтлы, которые никто не смотрел — `planned` исключаем
- **Рядом, вне скоупа:** `UNIQUE (user_id, tmdb_id)` в `media_items` и `getLibraryTmdbIds` тоже не различают фильм и сериал с одинаковым id
