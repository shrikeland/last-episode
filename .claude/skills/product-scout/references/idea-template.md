# Форматы файлов

## Карточка идеи — `ideas/NNN-<slug>.md`

`NNN` — трёхзначный сквозной номер (`001`, `002`, …), не переиспользуется даже после удаления карточки. `slug` — короткий, латиницей, через дефис: `episode-timeline`, `friends-ratings`, `year-in-review`.

```markdown
---
id: 1
slug: episode-timeline
lens: мёртвые данные
value: high
cost: S
status: new
created: 2026-07-27
---

# Лента просмотра

## Проблема
Человек отмечает серии каждый вечер, но нигде не может увидеть свой ритм
просмотра — только галочки внутри раскрытых сезонов, разбросанные по разным
тайтлам.

## Что видит пользователь
Новая секция на странице статистики: список последних отмеченных серий,
сгруппированный по дням. Строка — постер-миниатюра, название тайтла,
номер серии. Дни без просмотра пропускаются. Клик по строке ведёт на
карточку тайтла.

## Почему это дёшево / дорого
`episodes.watched_at` уже пишется при каждой отметке — см.
`lib/supabase/progress.ts:163`. Сейчас поле читается только в
`components/media/EpisodeRow.tsx:47` для одной строки внутри аккордеона.
Нужен один запрос с джойном к `media_items` и один серверный компонент.
Миграция не нужна.

## Скоуп
- `lib/supabase/progress.ts` — функция выборки последних просмотров
- `components/stats/WatchTimeline.tsx` — новый серверный компонент
- `app/(app)/stats/page.tsx` — вставить секцию
- Миграция БД: не нужна
- `'use client'`: не нужен, данные статичные

## Чего НЕ делаем
Без бесконечной прокрутки — показываем последние 30 дней и всё. Без фильтров
по тайтлу. Без экспорта. Без ленты просмотров друзей — это отдельная идея.

## Открытые вопросы
- Группировать по дням или по неделям, если человек смотрит редко?
```

### Что важно в каждой секции

**Проблема** — с точки зрения человека, а не системы. Не «поле не отображается», а «не могу вспомнить, что смотрел».

**Что видит пользователь** — описание интерфейса без кода. Достаточно подробное, чтобы можно было представить экран, но без вёрстки и названий пропсов. Если эту секцию невозможно написать — идеи нет, есть рефакторинг.

**Почему это дёшево / дорого** — с ссылками на конкретные файлы и по возможности строки. Владелец читает эту секцию, чтобы понять, влезет ли задача в вечер. Если ты пишешь «нужно будет посмотреть» — значит, ты недоисследовал, вернись и посмотри.

**Скоуп** — файлы, которые придётся тронуть. Три пункта всегда явно: нужна ли миграция, нужен ли `'use client'`, есть ли внешние вызовы (TMDB, Groq). Эти три вещи чаще всего превращают S в M.

**Чего НЕ делаем** — обязательная секция, здесь режется скоуп. Пиши сюда всё, что напрашивается само собой и что легко утянет задачу вдвое. Через месяц эта секция ценнее остальных: она защищает от «ну раз уж я здесь».

**Открытые вопросы** — то, что стоит решить перед реализацией. Пустая секция — нормально, удали её. Но если вопрос есть, лучше записать его сейчас, чем споткнуться о него в середине.

### Поля фронтматтера

| Поле | Значения |
|---|---|
| `id` | число, сквозное |
| `slug` | латиница через дефис, совпадает с именем файла |
| `lens` | название линзы ровно как в `lenses.md` |
| `value` | `high` / `medium` / `low` |
| `cost` | `S` / `M` / `L` |
| `status` | `new` / `planned` / `done` / `rejected` |
| `created` | `YYYY-MM-DD` |

## Реестр — `ideas/BACKLOG.md`

```markdown
# Бэклог идей

Обновлено: 2026-07-27

## Ротация линз

| Линза | Последний прогон |
|---|---|
| мёртвые данные | 2026-07-27 |
| тупики пути | 2026-07-27 |
| пустые состояния | — |
| ретеншн-петля | — |
| недожатая социалка | — |
| эвристики нильсена на экране | — |
| ввод и трение | — |
| персонализация по своим данным | — |

## Идеи

| # | Идея | Линза | Ценность | Цена | Статус |
|---|------|-------|----------|------|--------|
| 1 | [Лента просмотра](001-episode-timeline.md) | мёртвые данные | высокая | S | new |
| 2 | [Кликабельные жанры в статистике](002-clickable-genres.md) | тупики пути | средняя | S | new |
```

Ссылки относительные — обе стороны лежат в `ideas/`.

Строки только добавляются. Менять можно статус; удалять — нельзя, включая `rejected`. Отклонённая идея хранит знание о том, что владелец её уже рассмотрел и отверг, и без этой записи она вернётся на следующем прогоне.

Порядок строк — по номеру, а не по приоритету. Приоритет читается из колонок ценности и цены; переупорядочивание таблицы ломает сопоставление с номерами файлов.
