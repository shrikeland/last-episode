## Goal
После регистрации человек может уйти к форме входа, а ссылка из письма подтверждения ведёт на логин с тостом «почта подтверждена» — с любого устройства.

## Approach
Найдено при регистрации тестового аккаунта (2026-09-22):
- Экран «Письмо отправлено» (`app/(auth)/register/page.tsx`) — тупик: ни кнопки ко входу, ни способа исправить опечатку в email
- `app/auth/callback/route.ts` меняет `code` на сессию через `exchangeCodeForSession`. Это PKCE: нужен code verifier, который браузер сохранил при `signUp`. Письмо открыто на телефоне, в почтовом клиенте или другом браузере → обмен падает → редирект на `/register?error=confirmation_failed`, а страница регистрации этот параметр не читает. Человек видит пустую форму регистрации
- При этом почта к этому моменту уже подтверждена: Supabase помечает её на своём `/verify` и только потом присылает `code` на колбэк. Упал лишь автологин
- В удачном случае (тот же браузер) колбэк шлёт на `/email-confirmed`, но `proxy.ts` видит сессию на auth-странице и уводит в `/library` — страница подтверждения не показывается никогда

Решение — колбэк перестаёт логинить:
- Есть `code` → `/login?confirmed=1`. Нет → `/login?error=confirmation_failed` (ссылка протухла или уже использована — Supabase в этом случае присылает `error*` параметры вместо `code`)
- Логин по параметру показывает тост (sonner уже подключён) и убирает параметр из URL, чтобы тост не повторялся при перезагрузке
- `/email-confirmed` удаляется как недостижимая, её путь убирается из списка auth-страниц в `proxy.ts`
- Колбэк используется только для подтверждения регистрации (`emailRedirectTo` в `register/page.tsx`) — OAuth, magic link и сброса пароля в проекте нет, их не задеваем
- Шаблон письма в Supabase не меняем

## Risks / open questions
- Утверждение «почта подтверждена до редиректа с `code`» — это поведение GoTrue при PKCE-подтверждении. Если окажется не так, человек увидит тост «подтверждена», а логин ответит «Подтвердите email перед входом» — неприятно, но вход не ломает. Проверяется одной реальной регистрацией
- Человек больше не залогинен автоматически после подтверждения — осознанно (просьба владельца: логин + уведомление). Автовход с любого устройства возможен через `token_hash` + `verifyOtp`, но требует смены шаблона письма в дашборде Supabase
- Если человек уже залогинен и кликает ссылку, `proxy.ts` отправит его в `/library` раньше колбэка — как и сейчас
